# 小说转漫剧资产

把书名当作项目 ID 使用。项目 ID 是受信任资产库中的一级目录名，例如 `my-test` 或实际书名，不是本机路径。

## 工作流

1. 调用 `ai_drama_inspect`，传入用户给出的书名作为 `project_id`。如果找不到项目，先提示用户在工作台创建项目，不要自行创建项目或猜测路径。
2. 阅读扫描结果，基于小说片段生成严格 JSON 计划，并调用 `ai_drama_stage_proposal`，使用同一个 `project_id` 和 `project_fingerprint`。不要跳过暂存。
3. 向用户展示提案摘要、将创建的相对路径、识别出的复用资产和不确定项。计划至少覆盖片段中实际出现且可复用的角色、身份基准/造型、地点、道具、场次和镜头；不确定的信息写入 Markdown 的待补充项，不要编造媒体文件。
4. 只有用户明确确认后，才调用 `ai_drama_apply_proposal`，传入 `project_id`、`proposal_id` 和精确确认语句 `确认写入 <proposal_id>`。
5. 写入完成后说明真实创建了哪些 Markdown 和空资料槽；图片/视频生成是后续工作流，不能把空资料槽说成已生成媒体。

## 计划约束

计划字段必须包含：`title`、`summary`、`new_characters`、`look_additions`、`reuse_characters`、`new_locations`、`reuse_locations`、`new_props`、`reuse_props`、`new_scenes`、`reuse_scenes`、`notes`。

采用“场次容器 + 单镜头生产”的模型：场次只组织镜头、保存本场人物/地点/道具的结构化引用和连续性；每个镜头才是独立的生产单元。人物、地点、道具仍是项目级可复用主档，先在场次绑定，再按镜号范围继承到镜头。顶层目录仍为 `主要人物/场景/道具/分镜`。

场次下要提供 `scene_id`、`title`、`summary`、`character_refs`、`location_refs`、`prop_refs`、`cast`、`shots`；推荐同时提供 `location_bindings` 和 `prop_bindings`。绑定可使用资产名称（服务端会解析为精确项目相对路径），字段分别为 `location`/`prop`、`role`、`state`、`continuity`、`start_shot_id`、`end_shot_id`。旧计划只给 refs 也兼容，会自动生成全场默认绑定。每个镜头要提供 `id`、`title`、`content`，并补齐时间码、景别、运镜、台词、提示词、参考资产和状态；人物造型覆盖必须使用 `inherit`、`identity` 或 `look`。

提案写入每个新场次的 `场次资产表.md`，其中包含 `workbench:scene-assets` marker JSON 和人类可读表格；`场次.md` 仍保留“引用资产”文字，便于人工阅读。

## 提示词契约

提示词是可直接提交给对应工作流的画面指令，不是设定摘要，也不应包含 Markdown 标题或资料槽说明。

- 每个 `new_locations` 项必须给出 `prompt` 和 `negative_prompt`，分别写入场景的“场景图提示词”和“负面提示词”。
- 每个 `new_props` 项必须给出 `prompt` 和 `negative_prompt`，分别写入道具的“道具图提示词”和“负面提示词”。
- 每个 `shots` 项必须给出共享 `prompt` 和 `negative_prompt`。首尾帧的构图或状态不同，再补 `first_frame_prompt`、`first_frame_negative_prompt`、`last_frame_prompt`、`last_frame_negative_prompt`；缺省时工作台回退到共享镜头提示词。
- 不要在提案中创建 `task_prompt`。生成任务会从保存的资产提示词、引用资产和当次临时修改计算最终输入，并将实际提交的提示词冻结在任务记录中。图生视频同样由已保存镜头、场次、人物、场景、道具、项目设定和已选首尾帧组成任务输入。

## 镜头生产语义

提案只建立可保存的资产和镜头设计，不直接声称已经生成媒体。工作台会针对每个真实镜头按以下顺序生产：

所有图片任务的生成弹窗都会显示提示词和负面提示词；用户可在提交前临时修改，只影响本次任务，不回写人物、场景、道具或镜头 Markdown。人物、场景和道具也可以从各自资产库直接生成参考图；生成结果会归档回对应资产资料槽。

1. 镜头设计：保存画面、台词、景别、运镜、时长、共享提示词、可选的首尾帧提示词和人物造型覆盖。
2. 画面参考：可上传镜头参考图，也可使用已绑定场景、道具或人物的已选视觉图。在当前镜头点击“生成场景图”时，系统创建或复用项目级 `场景/<场次名>` 场景资产，将已保存的镜头 `prompt` 或 `content` 写入场景设定，并自动绑定到当前分镜场次。生成结果归档到该场景资产的场景图槽，不生成或使用分镜场次资料槽。生成候选仍须用户明确设为参考后才可作为首帧参考。这是可选输入，不应阻断只有文字设定的镜头。
3. 首帧：可在文生图和图生图之间切换。图生图最多选择两张已选人物、场景、道具或镜头参考图，可组合人物 + 场景（或道具）后生成；未选择参考时使用文生图。候选图必须由用户明确标为“已选”。
4. 尾帧：默认基于当前镜头已选首帧生成；图生图时可在首帧之外再选择一张人物、场景或道具参考图。候选图也必须明确标为“已选”。
5. 图生视频：只在首帧和尾帧均已选后提交。服务端会读取已保存的镜头、场次、人物/造型、地点、道具和项目设定作为文本信息，并只上传已选首帧和尾帧。

图生图的两张图片分别上传到工作流的两个 `LoadImage` 输入；只有一张时第二路复用第一张，选择两张时由 `LatentBlend` 混合两路编码后的 latent。修改工作流或 API 导出后，先在 ComfyUI 服务器更新文件，再执行工作台的“一键同步工作流”。

因此每个 `shots` 项至少要让 `content` 或 `prompt` 之一非空，并尽量补全 `duration`、`framing`、`camera`、`dialogue`、`references`、人物状态和连续性。不要在计划中伪造首帧、尾帧、候选图、成片路径或已提交任务；这些只会在工作台后续生成并归档。

已有资产放入对应的 `reuse_*`，不能放进 `new_*` 以覆盖。一个片段若只产生新人物或道具，也可以单独形成提案；若没有任何新资产或新增 LOOK，则不创建空提案。
